O que é Google Hacking?

Google Hacking — também conhecido como Google Dorking — é a prática de usar os operadores de busca avançada do Google para encontrar informações sensíveis ou expostas involuntariamente na internet. Não é necessário qualquer ataque ativo: toda a inteligência vem de dados que o próprio Google indexou.

O que são Google Dorks? DEFINIÇÃO

São consultas de busca especialmente formatadas que exploram os operadores avançados do Google para localizar arquivos, diretórios, dispositivos, credenciais e outras informações que normalmente não são visíveis em buscas comuns. O Google se torna uma poderosa ferramenta de OSINT (Open Source Intelligence).

Por que isso é poderoso? CONCEITO

Administradores mal configurados expõem acidentalmente arquivos, painéis de admin, cameras, logs e até senhas. O Google indexa tudo. Com a dork certa, você encontra esses vazamentos sem tocar no servidor.

⚠ AVISO LEGAL: Este material é exclusivamente educacional. O uso de Google Dorks para acessar sistemas sem autorização é crime (Lei 12.737/2012 no Brasil). Use apenas em sistemas que você tem permissão explícita para testar.
ORIGENS

Criada por Johnny Long em 2004, a Google Hacking Database (exploit-db.com/google-hacking-database) é um repositório público com milhares de dorks categorizadas, incluindo: arquivos sensíveis, senhas expostas, painéis de login, câmeras online, dispositivos IoT e muito mais.

>_ DICA: Combine múltiplos operadores em uma única busca para resultados muito mais precisos e filtrados. A arte do Google Hacking está na combinação estratégica.

Operadores Fundamentais

Estes são os blocos de construção do Google Hacking. Cada operador funciona como um filtro que restringe ou expande os resultados de busca. Dominá-los é o primeiro passo.

OPERADORES DE CONTEÚDO
site:
Restringe resultados a um domínio específico. Funciona com domínio completo ou TLD.
site:gov.br confidencial
inurl:
Busca pela palavra-chave dentro da URL da página. Ótimo para encontrar painéis.
inurl:admin/login.php
intext:
Procura o termo dentro do conteúdo visível da página.
intext:"password" site:pastebin.com
intitle:
Localiza páginas com a palavra-chave no título (<title>) da página.
intitle:"index of" /backup
filetype:
Filtra por extensão de arquivo. Aceita: pdf, doc, xls, sql, log, txt, xml, env…
filetype:sql "INSERT INTO users"
ext:
Alternativa ao filetype:, busca por extensão de arquivo específica.
ext:env "DB_PASSWORD"
OPERADORES DE LINK E CACHE
cache:
Exibe a versão em cache de uma página. Útil quando a original foi removida.
cache:site-alvo.com/admin
link:
Encontra páginas que apontam para uma URL. Mapeamento de relacionamentos.
link:empresa-alvo.com
related:
Retorna sites similares ou relacionados ao domínio informado.
related:empresa-alvo.com
info:
Exibe informações que o Google tem sobre uma URL específica.
info:empresa-alvo.com
OPERADORES LÓGICOS E ESPECIAIS
OPERADOR FUNÇÃO EXEMPLO
"aspas" Busca exata da frase entre aspas "index of" /uploads
-palavra Exclui resultados com esse termo login -site:github.com
OR / | Retorna A ou B (booleano) filetype:xls OR filetype:csv
AND Ambos os termos obrigatórios (implícito) admin AND password
* Coringa — qualquer palavra no lugar "usuário * senha *"
allinurl: Todos os termos devem estar na URL allinurl:admin php login
allintitle: Todos os termos no título da página allintitle:index backup 2024
>_ COMBINAÇÃO PODEROSA: site: + filetype: + intext: — restringe o domínio, o tipo de arquivo E o conteúdo. Resultado extremamente preciso.

Casos de Uso Reais

Exemplos práticos de como pentesters e pesquisadores de segurança combinam operadores para encontrar vulnerabilidades reais. Todos os exemplos são genéricos e para fins educacionais.

Caso 1 — Encontrar formulários com SQL Injection SQLI

Formulários PHP em sites que ainda usam queries vulneráveis tendem a ter parâmetros expostos na URL. A dork abaixo encontra páginas PHP com IDs na URL em um domínio específico.

SQL INJECTION CANDIDATES
// Parâmetros id= em páginas PHP (clássico SQLi) site:alvo.com.br inurl:"?id=" filetype:php // Outros parâmetros vulneráveis comuns site:alvo.com inurl:"?cat=" OR "?product=" OR "?page=" // Erro de banco exposto na página site:alvo.com intext:"mysql_fetch_array()" site:alvo.com intext:"SQL syntax"
Caso 2 — Documentos Corporativos Confidenciais DATA LEAK

Empresas frequentemente publicam documentos em servidores web sem perceber que o Google os indexa. PDFs com orçamentos, contratos e relatórios internos são comuns.

DOCUMENT LEAK
// PDFs e documentos Word confidenciais site:alvo.gov.br filetype:pdf intitle:"confidencial" // Planilhas financeiras expostas site:alvo.com.br filetype:xls intext:"salário" // Contratos em Word site:alvo.com.br filetype:doc intext:"contrato de prestação" // Apresentações internas site:alvo.com.br filetype:pptx intext:"uso interno"
Caso 3 — Vazamentos em Serviços de Terceiros THIRD-PARTY

Desenvolvedores frequentemente colam código, senhas e tokens em Pastebin, Gist e repositórios públicos. Uma busca cruzada com o domínio revela essas exposições.

THIRD-PARTY LEAKS
// Senhas e tokens em Pastebin site:pastebin.com "alvo.com" intext:"password" // Credenciais em GitHub Gist site:gist.github.com "alvo.com" "api_key" // Repositórios GitHub públicos com dados do alvo site:github.com "alvo.com.br" "password" // Trello/Notion com info sensível site:trello.com "alvo.com"
⚠ Estes exemplos demonstram o que um invasor poderia buscar. Como defensor, use as mesmas dorks nos seus próprios domínios para identificar exposições antes que outros o façam.
Caso 4 — Identificar Tecnologias e Versões FINGERPRINT

Páginas de erro e cabeçalhos padrão revelam versões de software. Informação valiosa para cruzar com CVEs conhecidos.

TECHNOLOGY FINGERPRINT
// Apache com versão exposta intitle:"Apache2 Ubuntu Default Page" site:alvo.com // IIS default page intitle:"IIS Windows Server" site:alvo.com // Django debug page (NEVER in production) intext:"DEBUG = True" site:alvo.com // Laravel .env exposto inurl:"/.env" intext:"APP_ENV=production"

Shodan — Filtros e Comandos

Enquanto o Google indexa páginas web, o Shodan indexa dispositivos conectados à internet: servidores, câmeras, roteadores, sistemas SCADA, IoT e tudo que tem um IP. É a ferramenta definitiva de reconhecimento de infraestrutura.

O que o Shodan encontra? VISÃO GERAL

O Shodan faz varredura contínua de todos os IPs públicos, conecta nas portas e captura os banners de resposta. Com isso, cria um banco de dados pesquisável de serviços, versões de software, configurações e vulnerabilidades — tudo sem precisar atacar nada.

🔧 FILTROS FUNDAMENTAIS
hostname:
Filtra resultados pelo nome de host. Ideal para mapear toda a infraestrutura de um domínio.
hostname:empresa.com.br
ip:
Busca por um IP específico. Retorna todos os serviços e portas abertas naquele endereço.
ip:200.150.100.50
org:
Filtra por organização (ASN/WHOIS). Encontra todos os servidores de uma empresa.
org:"Banco do Brasil"
net:
Filtra por faixa de IPs em notação CIDR. Útil para varrer blocos inteiros.
net:200.150.0.0/16
country:
Filtra por país usando código ISO de 2 letras.
country:BR port:22
city:
Filtra por cidade específica. Combine com outros filtros para precisão.
city:"São Paulo" port:3389
🔌 FILTROS DE SERVIÇO E PORTA
port:
Filtra por porta específica. Encontra todos os servidores com aquela porta aberta.
port:22 country:BR
product:
Filtra pelo produto/software identificado no banner. Excelente para encontrar versões vulneráveis.
product:"Apache httpd" country:BR
version:
Filtra por versão específica de um produto. Use com CVEs para encontrar sistemas vulneráveis.
product:"OpenSSH" version:"7.4"
os:
Filtra pelo sistema operacional identificado. Útil para enumerar Windows Servers expostos.
os:"Windows Server 2016" country:BR
📡 FILTROS DE CONTEÚDO E BANNER
banner:
Busca texto dentro do banner de resposta do serviço. Muito flexível e poderoso.
banner:"220 ProFTPD" country:BR
http.title:
Filtra pelo título HTML da página web. Similar ao intitle: do Google.
http.title:"Dashboard" country:BR
http.html:
Busca texto dentro do HTML retornado. Encontra painéis e sistemas específicos.
http.html:"phpMyAdmin" country:BR
ssl.cert.subject.cn:
Filtra pelo Common Name do certificado SSL/TLS. Mapeia infraestrutura via certificados.
ssl.cert.subject.cn:"*.empresa.com.br"
